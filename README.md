# КБЖКХ калькулятор

PWA-калькулятор суммарной пищевой ценности (калории, белки, жиры, кальций, фосфор,
включая соотношение Ca:P) набора кормовых позиций для домашнего насекомоядного питомца.

Реализовано по дизайн-хэндоффу из `.claude/Projects/calory_hedge/project/design_handoff_kbzhkh/`
(ТЗ, макет, дизайн-система Modernist, тестовые данные).

## Стек

Никакой сборки — чистые HTML/CSS/JS, без npm-зависимостей и билд-шага.
Данные — в IndexedDB ([db.js](db.js)), offline — через service worker ([sw.js](sw.js)).
Это значит, что папку можно целиком заархивировать и передать кому угодно: достаточно
раздать её любым статическим сервером (или открыть `index.html` напрямую — часть
функциональности вроде IndexedDB и service worker в большинстве браузеров при этом
тоже работает, но PWA-«установка» требует http(s)).

Локальный запуск с сервером (рекомендуется для полной проверки PWA):

```bash
npx serve .
```

## Файлы

- `index.html` — разметка и подключение стилей/скриптов.
- `style.css` — токены дизайн-системы Modernist + компоненты приложения.
- `app.js` — состояние, бизнес-логика, рендеринг экранов.
- `db.js` — обёртка над IndexedDB (стораджи `positions`, `savedCalcs`, `meta`).
- `seed-data.js` — 11 затравочных позиций (насекомые для ежей), подмешиваются в
  справочник при первом запуске (новые позиции — при первом запуске после
  обновления, см. `ensureSeedPositions` в `app.js`). Вес/калорийность/белки/жиры/
  Ca/P — из таблицы поставщика корма, на сырой вес насекомого (не сухое
  вещество, в отличие от черновых оценок в исходном ТЗ). `calciumPercent`/
  `phosphorusPercent` — это колонка соотношения Ca:P из таблицы (напр. `1`/`2`
  означает Ca:P = 1:2), а не абсолютный % массы: у части позиций в исходной
  таблице абсолютные mg-колонки Ca/P расходились со своей же колонкой
  соотношения, соотношение — единственные согласованные данные по всем
  позициям. Из-за этого суммы «Кальций/Фосфор, г» на главном экране отражают
  верное соотношение, но не реальные граммы.
  `image` — фото товара с t-rexfood.ru (есть у исходных 8 позиций; у 3 новых
  из таблицы поставщика фото пока нет), вариант (живой/замороженный) утверждён
  пользователем по каждой позиции, приведено к 200×200 JPEG data URI тем же
  кодом, что и загрузка фото пользователем.
- `manifest.webmanifest`, `sw.js`, `icons/` — PWA-артефакты.
- `version.js` — номер релиза (`APP_VERSION`), см. «Версионирование» ниже.
- `api/feedback.js` — Vercel serverless function, создаёт issue в GitHub по тексту
  из экрана «Настройки → Доработка», см. «Доработка через приложение» ниже.

## Версионирование

Номер релиза — единственная переменная `APP_VERSION` в [version.js](version.js),
отображается в подвале главного экрана приложения. При каждой доработке:

1. Увеличить `APP_VERSION` (semver: patch — фикс, minor — новая функциональность, major — breaking change).
2. Добавить/обновить `./version.js` в service worker precache-листе, если файл ещё не в списке (уже добавлен).
3. Указать версию в сообщении коммита/MR (например, заголовок или строка `Version: vX.Y.Z`).

## Деплой на Vercel

Статический сайт, специальная конфигурация сборки не нужна (Vercel определит
"Other" / статический проект и просто раздаст файлы как есть).

1. Запушить репозиторий на GitHub.
2. На vercel.com → **Add New → Project** → импортировать репозиторий.
3. Framework Preset — **Other**, Build Command / Output Directory — оставить пустыми.
4. Deploy.

## Бизнес-логика

```
итог_калорий  = кол-во × вес_1шт(г) × калории_на_грамм
итог_параметра = кол-во × вес_1шт(г) × (процент / 100)   // белки/жиры/кальций/фосфор

Ca:P = суммарный_кальций / суммарный_фосфор
доля_от_массы(белки|жиры) = суммарный_параметр / суммарная_масса_расчёта × 100
```

## Настройки → Предупреждения

Экран «Настройки» (шестерёнка в шапке главного экрана) хранит пороги в `meta.settings`:
`fatMaxPercent` («выше значения»), `caPMinRatio`/`proteinMinPercent` («ниже значения»),
`caloriesMin`/`caloriesMax` (диапазон нормы). Пустое поле — ограничение выключено.
Дефолты (для первого запуска и для любого поля, ранее сохранённого пустым): жир ≤15%,
белок ≥30%, Ca:P ≥1:1, калории ≥50 ккал; `caloriesMax` без дефолта.
На главном экране соответствующая цифра (калории, Ca:P, % массы белков/жиров)
подсвечивается красным (`.kbz-alert`), если расчёт выходит за настроенные рамки.
Поля сохраняются сразу при вводе, с коротким тостом «Сохранено» внизу экрана.

Полное ТЗ — в `ТЗ_исходный.md` и `ТЗ_финальное.md` дизайн-хэндоффа.

## Фото позиции

В карточке позиции (экран «Позиции» → редактирование) можно загрузить фото насекомого.
Загруженная картинка сразу ресайзится и обрезается по центру в квадрат
`POSITION_IMAGE_SIZE` (200×200, см. [app.js](app.js)) через canvas и сохраняется как
JPEG data URI прямо в объекте позиции (поле `image`) — отдельного object store не
заведено, файл никуда не грузится. Превью показывается над названием в списках
«Позиции» и «Добавить в расчёт»; у позиций без фото блок просто не рендерится.

## Настройки → Доработка

Кнопка «Сообщить о доработке» открывает форму с одним многострочным полем и кнопкой
«Отправить». Текст уходит POST-запросом на `/api/feedback` — это Vercel serverless
function ([api/feedback.js](api/feedback.js)), которая от имени владельца репозитория
создаёт issue в `kingd1998/kbzhkh-pwa` через GitHub REST API. Токен нигде не хранится в
клиентском коде.

**Настройка (один раз, до первого использования на деплое):**

1. Создать fine-grained personal access token на GitHub: Settings → Developer settings →
   Personal access tokens → Fine-grained tokens. Repository access — только
   `kingd1998/kbzhkh-pwa`. Permissions — **Issues: Read and write**, больше ничего.
2. В проекте на vercel.com → Settings → Environment Variables добавить
   `GITHUB_TOKEN` со значением токена (Production/Preview — по необходимости).
3. Передеплоить проект, чтобы переменная окружения подхватилась.

Эндпоинт не имеет отдельной защиты от спама/абьюза сверх ограничения длины текста
(4000 символов) — это приемлемо, пока адрес деплоя не публикуется публично.
