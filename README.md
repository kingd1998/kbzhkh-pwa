# КБЖКХ калькулятор

PWA-калькулятор суммарной пищевой ценности (калории, белки, жиры, кальций, фосфор,
включая соотношение Ca:P) набора кормовых позиций для домашнего насекомоядного питомца.

Реализовано по дизайн-хэндоффу из `.claude/Projects/calory_hedge/project/design_handoff_kbzhkh/`
(ТЗ, макет, дизайн-система Modernist, тестовые данные).

## Стек

Никакой сборки — чистые HTML/CSS/JS, без npm-зависимостей и билд-шага.
Данные — в IndexedDB ([db.js](db.js)), offline — через service worker ([sw.js](sw.js)).
Это значит, что папку можно целиком заархивировать и передать кому угодно: достаточно
раздать её любым статическим сервером (или открыть `index.html` напрямую — часть
функциональности вроде IndexedDB и service worker в большинстве браузеров при этом
тоже работает, но PWA-«установка» требует http(s)).

Локальный запуск с сервером (рекомендуется для полной проверки PWA):

```bash
npx serve .
```

## Файлы

- `index.html` — разметка и подключение стилей/скриптов.
- `style.css` — токены дизайн-системы Modernist + компоненты приложения.
- `app.js` — состояние, бизнес-логика, рендеринг экранов.
- `db.js` — обёртка над IndexedDB (стораджи `positions`, `savedCalcs`, `meta`).
- `seed-data.js` — 8 затравочных позиций (насекомые для ежей), подмешиваются в
  справочник при первом запуске. `caloriesPerGram`, `calciumPercent` и
  `phosphorusPercent` у всех позиций — `0` (реальные значения не найдены в
  исходном источнике), дозаполнить вручную перед реальным использованием.
- `manifest.webmanifest`, `sw.js`, `icons/` — PWA-артефакты.
- `version.js` — номер релиза (`APP_VERSION`), см. «Версионирование» ниже.

## Версионирование

Номер релиза — единственная переменная `APP_VERSION` в [version.js](version.js),
отображается в подвале главного экрана приложения. При каждой доработке:

1. Увеличить `APP_VERSION` (semver: patch — фикс, minor — новая функциональность, major — breaking change).
2. Добавить/обновить `./version.js` в service worker precache-листе, если файл ещё не в списке (уже добавлен).
3. Указать версию в сообщении коммита/MR (например, заголовок или строка `Version: vX.Y.Z`).

## Деплой на Vercel

Статический сайт, специальная конфигурация сборки не нужна (Vercel определит
"Other" / статический проект и просто раздаст файлы как есть).

1. Запушить репозиторий на GitHub.
2. На vercel.com → **Add New → Project** → импортировать репозиторий.
3. Framework Preset — **Other**, Build Command / Output Directory — оставить пустыми.
4. Deploy.

## Бизнес-логика

```
итог_калорий  = кол-во × вес_1шт(г) × калории_на_грамм
итог_параметра = кол-во × вес_1шт(г) × (процент / 100)   // белки/жиры/кальций/фосфор

Ca:P = суммарный_кальций / суммарный_фосфор
доля_от_массы(белки|жиры) = суммарный_параметр / суммарная_масса_расчёта × 100
```

Полное ТЗ — в `ТЗ_исходный.md` и `ТЗ_финальное.md` дизайн-хэндоффа.
